# CLI Command Reference

Use this reference only when exact `rdx` command syntax or examples are needed. For implementation guidance, start with `./references/guide-cli.md`.

## Installation

Install the published CLI globally:

```sh
npm install -g rdx-cli
```

Verify the executable:

```sh
rdx --help
rdx config show
rdx llm
```

`rdx-cli` publishes the `rdx` binary. Treat it as a workflow coordinator: it prepares files, reads Gateway state, verifies local signatures, notarizes, submits, and tracks artifacts. It does not store private keys.

## Shared Output Flag

All commands accept the shared output flag:

```sh
rdx --format json <command>
rdx --format text <command>
```

JSON is the default and should be used by agents unless a human-readable one-line value is explicitly needed.

## Root And Config Commands

### `rdx llm`

Print the embedded Markdown guide for coding agents.

Example:

```sh
rdx llm
```

Use this as the operational quickstart before automating a workflow.

### `rdx config show`

Print resolved CLI configuration, including network and artifact root.

Example:

```sh
rdx config show
rdx --format text config show
```

Check this before preparing a transaction because `rdx` defaults to mainnet unless config says otherwise.

## Account Commands

### `rdx account derive --public-key <hex>`

Derive the virtual account address for the resolved network from an Ed25519 public key.

Example:

```sh
rdx account derive --public-key 1111111111111111111111111111111111111111111111111111111111111111
```

This is offline derivation. It does not prove the account exists on-ledger.

### `rdx account show <accountAddress>`

Read account details through Gateway.

Example:

```sh
rdx account show account_rdx1...
```

Use this for account-scoped state inspection without creating transaction artifacts.

### `rdx account fungibles <accountAddress>`

Read fungible token balances for an account.

Example:

```sh
rdx account fungibles account_rdx1...
```

Use this command instead of inventing a custom balance query in CLI code.

### `rdx account nfts <accountAddress>`

Read non-fungible resources for an account.

Example:

```sh
rdx account nfts account_rdx1...
```

Use this for Gateway-shaped NFT reads; keep portfolio aggregation outside the CLI unless product language requires it.

## Template Commands

### `rdx template print subintents`

Print a `subintents` workflow file template.

Example:

```sh
rdx template print subintents > tx/subintents.json
```

### `rdx template print signing-request`

Print a signing request template.

Example:

```sh
rdx template print signing-request
```

Usually signing requests are generated by `tx prepare` or `subintent prepare`; use this command for schema discovery.

### `rdx template print signature-template`

Print a fillable signature template with placeholder public key and signature values.

Example:

```sh
rdx template print signature-template > tx/signature-template.json
```

The placeholders must be replaced before importing signatures.

### `rdx template print signature-file`

Print an empty signature file.

Example:

```sh
rdx template print signature-file > tx/signatures.json
```

Use this for hand-built or batch-imported out-of-band signature files.

## Transaction Artifact Commands

### `rdx tx prepare --manifest <file> [--notary-file <file>] [--subintents <file>]`

Prepare root transaction artifacts from a Transaction Manifest V2 file.

Example:

```sh
rdx tx prepare --manifest ./tx/root.rtm --notary-file ./tx/notary.json
rdx tx prepare --manifest ./tx/root.rtm --subintents ./tx/subintents.json --notary-file ./tx/notary.json
```

This writes `prepared.json`, `transactionIntent.json`, `staticAnalysis.json`, signing requests, and signature templates under the transaction artifact directory. If `--notary-file` is omitted, the command uses resolved config notary settings.

### `rdx tx add-signatures <transactionId> --file <file> [--file <file> ...]`

Import out-of-band signatures into a prepared transaction artifact.

Example:

```sh
rdx tx add-signatures txid_example --file ./tx/signatures/intent-signature.json
rdx tx add-signatures txid_example --file ./tx/signer-a.json --file ./tx/signer-b.json
```

Use this for intent signatures and later for the notary signature. The command accepts signature files, batch files, or filled templates.

### `rdx tx notarize <transactionId>`

Create notary signing artifacts after required intent signatures are present.

Example:

```sh
rdx tx notarize txid_example
```

This writes the signed transaction intent and a notary signing request/template. It does not submit the transaction.

### `rdx tx submit <transactionId>`

Compile and submit a notarized transaction, then persist submit results.

Example:

```sh
rdx tx submit txid_example
```

Use this after importing the filled notary signature.

### `rdx tx status <transactionId> [--read-only]`

Query Gateway transaction status and optionally update local artifacts.

Example:

```sh
rdx tx status txid_example
rdx tx status txid_example --read-only
```

Use `--read-only` when inspection must not mutate local transaction artifacts.

### `rdx tx path <transactionId>`

Locate a transaction artifact directory.

Example:

```sh
rdx tx path txid_example
rdx --format text tx path txid_example
```

Use text output when a script only needs the path.

### `rdx tx list [filters]`

List local transaction artifacts.

Options:

- `--pattern <text>`
- `--regex <pattern>`
- `--network mainnet|stokenet`
- `--status prepared|notarized|submitted`
- `--with-network-status`
- `--update-network-status`

Examples:

```sh
rdx tx list
rdx tx list --pattern root.rtm
rdx tx list --network stokenet --status prepared
rdx tx list --with-network-status
rdx tx list --update-network-status
```

Use `--with-network-status` for a read-through status check and `--update-network-status` when local artifacts should be refreshed.

### `rdx tx history <accountAddress> [--limit <n>]`

Read account transaction history through Gateway.

Example:

```sh
rdx tx history account_rdx1... --limit 10
```

This is a read command. It does not require signing and does not change transaction lifecycle artifacts.

## Subintent Commands

### `rdx subintent prepare --manifest <file> --header <file> [--root-manifest <file>] [--no-preview]`

Prepare a standalone Subintent artifact for signing.

Example:

```sh
rdx subintent prepare --manifest ./tx/child.rtm --header ./tx/subintent-header.json
rdx subintent prepare --manifest ./tx/child.rtm --header ./tx/subintent-header.json --root-manifest ./tx/preview-root.rtm
rdx subintent prepare --manifest ./tx/child.rtm --header ./tx/subintent-header.json --no-preview
```

Use `--root-manifest` when previewing the subintent through a temporary root manifest. Use `--no-preview` only when preview is intentionally skipped.

### `rdx subintent build --prepared <file> --signature <file>`

Build a signed partial transaction from a prepared Subintent and signature file.

Example:

```sh
rdx subintent build --prepared ./subintents/subintent_hash/prepared-subintent.json --signature ./tx/subintent-signature.json
```

The output includes the signed partial transaction path and hex.
